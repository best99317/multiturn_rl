## 🧠 Introduction

This project introduces a novel training framework where each assistant response is rewarded by how much it **reduces the model’s uncertainty**, measured via entropy over recommendations—*without needing ground-truth labels*. This entropy-based reward is applied during fine-tuning with **Supervised Fine-Tuning (SFT)** and **Direct Preference Optimization (DPO)**. The approach leads to more strategic and confident interactions, improving both **recommendation accuracy** and **dialogue efficiency** on benchmark datasets like **Inspired** and **ReDial**.

---

## ✨ Features

- Fine-tuning LLMs using **entropy reduction as a reward**.
- Multi-turn conversational simulation with assistant and user models.
- Evaluation using recommendation list and simulated conversation.

## 🚀 Datasets
Under folder ```datasets/{dataset}/``` where ```{dataset}``` could be ```inspired``` or ```redial```
- ```raw``` folder stores the original datasets.
- ```multiturn``` folder stores the processed version in the multiturn conversation format.
- ```DPO_turnwise/combined_all_turns.csv``` stores all the conversation pairs generated for DPO finetuning.
- ```DPO_entropy/DPO_entropy_reduced.csv``` and ```DPO_entropy/DPO_turn_entropy_reduced.csv``` store the DPO datasets relabeled with entropy reduction metrics.
- ```sft_generated``` store the data with high reward filtered from the DPO datasets.


## 🚀 Usage

### Generating Simulated Conversations for DPO
- Under folder ```datasets```, run ```generate_turnwise_DPO_pair.ipynb``` or ```generate_turnwise_DPO_pair.py``` to generate DPO completion and conversation pairs. 
- One can specify to use local models or bedrock call, number of turns of the conversation, model name of the bedrock call, etc., with the ```create_config``` and ```TurnWiseConfig``` classes.
- For verifiable intermediate results, the completion pair is generated by turn, with the result of each turn stored under folder ```datasets/{dataset}/DPO_turnwise/{model}/```, and is combined using the ```combine_all_turns``` function with results stored in ```datasets/{dataset}/DPO_turnwise/{model}/combined_all_turns.csv```
- The default evaluation metric for choosing among the pairs is the reward from CollabLLM.
- For entropy reduction, ```generate_entropy_data.ipynb``` or ```generate_entropy_data.py```. The main logic is in the function ```process_csv_row```, where for each conversation, a last user reponse is generated and then the conversation is passed on to ```_calculate_entropy_for_conversation``` for turn entropy and conversation entropy reduction. The result is stored in ```datasets/{dataset}/DPO_entropy/DPO_turn_entropy_reduced.csv``` and ```datasets/{dataset}/DPO_entropy/DPO_entropy_reduced.csv``` respectively.

### Filtering Simulated Conversations with high reward for SFT
- This is done in ```datasets/pick_highreward_sft.ipynb``` where one can specify the metric and a ```.csv``` file generated for DPO to filter from.

### Run Supervised Fine-Tuning (SFT) and Direct Preference Optimization (DPO)
One can specify the data path, script path, model output path, and other arguements in the script and run. **Fill in your own huggingface token and wandb api key before executing the scripts.**

```bash
./scripts/sft_inspired.sh
```

```bash
./scripts/dpo_offline_redial.sh
```

### Evaluation with Recommendation List

- Generate recommendation list by running ```evaluation/zeroshot_test/generate_reclist.ipynb``` and specify ```dataset = "inspired"```,  ```alg = 'DPO'```, the path to store result ```to_json```, and other arguments in the ```main()``` function.

- Evaluate the generated recommendation list by running ```evaluation/zeroshot_test/calculate_recall.ipynb```. Specify the dataset, model, json result path by setting
```
dataset = 'inspired'
model = "llama3-2-1b-instruct"
alg = 'sft_generated'
file_name = '_test.jsonl' if alg == 'vanilla' else '_test_turn_entropy.jsonl' 
pred_json = f'test_res/{alg}/{dataset}/{model}/{dataset}{file_name}'
```


### Evaluation with Simulated Conversations

- Use ```generated_testsets/generate_testset.ipynb``` or ```generate_testset.py``` to generate simulated conversations between the fine-tuned models as the assistant and the user simulator based on the testsets of Inspired and ReDail. The generated conversations are stored under ```generated_testsets/multiturn_test```.
- Use ```question_and_hit_turns_counter.ipynb```, ```interactivity_score.ipynb```, etc., to evaluate the generated test conversations.
